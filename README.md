# FastNote

FastNote 是一个使用 Tauri、React 和 TypeScript 开发的跨平台笔记应用，内置可调用工具的 AI 笔记助手。

## 功能特性

- ✅ 笔记管理：创建、编辑、删除笔记，实时自动保存
- ✅ 分组管理：创建、编辑、删除分组，支持把笔记拖拽到分组上快速归类
- ✅ 回收站：删除先进回收站（可还原），也可以彻底删除 / 清空；超过 30 天的会自动清理
- ✅ 双编辑器：Monaco Editor 与 Markdown 编辑器一键切换
- ✅ 笔记导出：导出为文件（保存对话框）
- ✅ 搜索与排序：按标题/内容搜索（支持中文宽松匹配），按更新时间/创建时间/标题排序
- ✅ 欢迎面板：统计概览与最近更新的笔记
- ✅ 错误兜底：任何界面异常都会显示错误卡片而不是白屏

## AI 笔记助手

### 配置

在对话面板右上角的 ⚙️ 打开**统一的「AI 设置」窗口**，所有 AI 设置都在这一个地方（左侧分四个标签页）：

| 标签 | 内容 |
| --- | --- |
| 服务商 | 新增/编辑/删除服务商（OpenAI 兼容 / Claude / Gemini），拉取与勾选可用模型 |
| 对话行为 | 深度思考最少字数、最多工具轮数（**默认 0 = 不限制**）、思考过浅是否重来、流式输出开关、自动生成标题、默认开启操作确认、是否显示工具轨迹 |
| 上下文 | 上下文预算 token、始终保留的最近消息条数、单个工具结果注入上限、一键恢复默认 |
| 记忆 | 前置提示词 / 长期记忆的条数状态与入口（💡 按钮，列表独立编辑） |

设置**存在数据库里**（SQLite 的 `app_settings` 键值表，启动时自动建表），读取时逐项处理：

- 表里有该键 → 用库里的值
- 表里没有该键（新增设置/首次运行） → 用代码里的默认值
- 首次运行会把老版本存在 localStorage 的设置/记忆自动迁移进库，然后清掉旧数据

因此新增设置项不需要迁移脚本，也不会出现"升级后设置丢失"。对话面板在右侧，可拖动边缘调整宽度，也可折叠。

**API Key 不以明文入库**：写入前用 AES-256-GCM 加密（`enc:v1:` 前缀 + 随机 nonce），密钥保存在数据库同目录的 `fastnote.key`（数据库文件里没有它），并与当前 Windows 用户 + 机器名混合派生 —— 单独拷走数据库文件解不开。升级前遗留的明文记录会在下次读取时**自动加密迁移**，无需手动操作。

### AI 记忆 / 前置提示词

点对话面板右上角的 💡 按钮打开设置：输入框回车即可添加，列表形式展示，每条都能**编辑、删除、停用**。

启用中的内容会追加到**每次请求**的系统提示词末尾，所以它同时是两个东西：

- **默认前置提示词**：如"回答先给结论""始终用简体中文""代码块标注语言"
- **长期记忆**：如"我是前端开发者，常写技术笔记""项目代号 FastNote，笔记都要带日期"

数据保存在本机（localStorage），重启应用自动恢复。相比把要求写进每轮对话，它不占历史上下文、也不会被上下文压缩丢掉了。

### 能做什么（共 25 个工具）

| 分类 | 工具 |
| --- | --- |
| 查找 | 搜索笔记、列出笔记（可按分组/条数）、读取笔记（**默认只读前 200 行**，可指定行范围）、读取当前打开的笔记、按行范围读取、读取分组、查看回收站 |
| 写入 | 创建笔记、批量创建笔记、追加内容（不覆盖原文）、修改笔记、修改当前笔记 |
| 按行编辑 | **按行替换**（只改指定区间）、指定行后**插入**、**删除**指定行、**定点替换文本**（改错别字/统一措辞） |
| 删除 | 删除笔记（进回收站）、还原笔记、彻底删除、清空回收站 |
| 分组 | 创建分组、重命名分组、删除分组、移动笔记 |
| 导航 | 打开笔记（切换到指定笔记） |

「删除分组」不会彻底删除笔记：默认只让组内笔记变为未分类，勾选后也是**移入回收站**（可还原）。

### 长文处理（1000 行也不用从头读到尾）

读取返回的是**带行号的行窗口**（形如 `12| 正文…`，行号只用于定位），配合按行编辑工具：

- 改第 900 行 → 读取 `startLine=880&lineCount=40` 只取那一段 → `replaceLines` 只写回这一段，**前后内容原样保留**，不做全文覆盖
- 加内容 → `insertLines`（指定行之后）或 `appendToNote`（末尾）
- 删内容 → `deleteLines`；改词/错别字 → `replaceInNote`
- 提示词内已写明「长文分段读写」工作流，并明确禁止把上千行整篇塞进一次 `updateNote`

### 上下文管理（记忆压缩）

对话变长后不会把全部历史硬塞给模型（那正是"上下文太长 → 模型开始乱答、不思考"的根源）：

1. **单条瘦身**：超长消息（粘贴的长文、工具回传）只留头 1200 / 尾 400 字，中间折叠
2. **工具结果瘦身**：每轮回传的结果截到 1500 字，更早的压缩到 400 字（只保留最近 2 条原样）
3. **滑动窗口 + 摘要**：历史超过预算（约 14k token）时，更早的部分压成一段**要点摘要**（保留长期偏好、已确认结论、笔记 ID、未完成事项），只把「摘要 + 最近 8 条」发给模型；同一段只摘要一次并缓存
4. **摘要失败有兜底**：退化为"更早的 N 条对话已省略"，绝不静默丢上下文

界面上的历史始终完整，压缩只作用于发给模型的内容。

### 交互细节

- **深度思考**：每次回复都先输出 `<thinking>…</thinking>` 再回答；思考折叠在「思考 · …」一行里，点开可看全文。模型写歪的标签（`<tool_call>`、`<function_call>`、`<Thought>` 等）会自动归一化后再解析，不会再漏执行或残留到正文里。
- **工具轨迹**：实际执行过的每个工具各占一行（如 `打开笔记 · #16 · 《白雪公主》`），**点击可展开调用 JSON 与执行结果**；失败是红色并带原因。工具是按顺序逐个执行、逐条出现的。
- **不做假承诺**：回复里若声称"已打开/已创建/已删除"却没有对应的成功工具记录，会自动追加一条 ⚠️ 提示，避免被误导。
- **消息时间**：用户消息在气泡下方、AI 回复在正文下方显示时间（今天为 `HH:mm`，昨天带"昨天"，更早带日期）；历史消息用的是数据库里的真实时间。
- **停止与继续**：生成中点「停止」会立即停下（正在执行的操作不会再继续、正在飞的请求结果会被丢弃），并且**马上就能发下一条**；一句「继续」可以让模型接着处理未完成的任务。
- **历史锚点**：对话右侧垂直居中是一列**横线**，一条用户消息一条；当前查看的那条更长更亮，鼠标移入时附近的横线呈波浪式伸长；悬停显示该条提问摘要，点击平滑跳转，滚轮浏览历史时高亮跟着走。条数超过可用高度时自动等距采样，**永不溢出、无滚动条**。

## 技术栈

- **前端**：React 19 + TypeScript + Vite
- **桌面端**：Tauri 2（Rust 后端，26 个命令）
- **编辑器**：Monaco Editor + md-editor-rt（Markdown/KaTeX/Mermaid/代码高亮）
- **样式**：Tailwind CSS

## 开发

### 安装依赖

```bash
pnpm install
```

### 开发模式

```bash
pnpm tauri:dev      # 桌面端（推荐）
pnpm dev            # 仅前端（浏览器打开，AI 与本地数据库相关功能不可用）
```

### 构建

```bash
pnpm tauri:build    # 打包桌面应用
pnpm build          # 仅前端产物（tsc + vite build）
```

### 测试与审计

```bash
pnpm test:parse     # AI 输出解析层回归测试（Node 直接跑 TS，48 项）
pnpm check          # 一致性审计：死码 / 冗余 import / 工具定义对齐 / Rules of Hooks
```

改动 AI 解析、工具定义或对话组件后，建议这两个都跑一遍——它们覆盖了历史上出现过的故障形态（工具标签漏写、思考被误判、回答被覆盖、标题被污染、谎报操作等）。

## 设计约定（二次开发前请先读）

1. **AI 输出解析只有一处实现**：`src/aiChatParse.ts`。流式渲染与最终消息都走同一套规则，避免出现"流式显示的"和"最终落地的"不一致（历史上因此出现过闪烁、正文重复、工具被静默丢弃）。
2. **标签协议**：模型输出形如 `<thinking>…</thinking>` + `<tool_calls>[{"name":"…","args":{…}}]</tool_calls>` + 正文。解析层对三种畸形写法都做了兜底：漏写开标签、漏写闭标签、JSON 写到一半。
3. **正文只取思考块之后的内容**：模型抢先说的半句不算正文（否则会与真正的回答重复）。
4. **不显示"可能被丢弃的内容"**：本轮不是以 `<thinking>` 开头时，正文先按住不显示；只有确认模型根本不写思考时才放行，避免"闪一下又消失"。
5. **工具定义有 7 处需要同步**（`TOOL_DEFS`、标签、执行器、提示词、轨迹详情、确认文案、事实校验规则），`pnpm check` 会校验它们是否对齐——新增工具时记得跑。
6. **组件内 hooks 必须全部写在条件早退之前**（`pnpm check` 已把这条做成规则），否则开/关面板会导致 hook 数量不一致、React 直接卸载整棵树（表现为整页空白）。
7. **发送锁按"轮次编号"管理**：点停止会立即作废当前轮次并解锁，旧循环在下一个检查点安静退出，不会再去改界面或执行工具。
